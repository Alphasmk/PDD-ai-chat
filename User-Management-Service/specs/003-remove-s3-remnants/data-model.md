# Data Model: текущий пользователь и нейтральные тестовые данные

**Date**: 2026-09-27 | **Spec**: [spec.md](spec.md)

Это описание неизменяемой модели для проверок 003; новые поля, таблицы и миграции не проектируются.

## Пользователь

| Поле | Тип / правило | Полный профиль | PATCH response |
|---|---|---|---|
| id | UUID подтверждённого аккаунта | Да | Нет |
| name | string; существующая валидация Name | Да | Да |
| surname | string; существующая валидация Name | Да | Да |
| username | уникальная string | Да | Да |
| email | валидный уникальный email | Да | Да |
| phone_number | string или null; уникальность ненулевого значения | Да | Да |
| created_at | datetime UTC | Да | Нет |
| updated_at | datetime UTC или null | Да | Нет |
| password_hash | PasswordHash / строка хранения | Нет | Нет |

UserEntity использует value objects; UserReadDTO содержит ровно восемь публичных полей. ORM содержит девять полей с password_hash. Преобразования между слоями не меняются. Схема содержит users и служебную alembic_version без отношений с другими доменными сущностями.

Baseline `2026_09_27_users_without_images_baseline.py`, revision `users_no_images_20260927` и его head остаются прежними. Исторические миграционные идентификаторы сохраняются и проверяются существующим тестом; перехода схемы для 003 нет.

## Тестовые данные

Независимые Alice/Bob позволяют проверить привязку me к bearer-субъекту. Чужие id/user_id в JSON не перенаправляют PATCH. Нейтральное дополнительное поле `unsupported_field: "ignored"` не имеет модели или хранилища в приложении.

| Действие | Ожидаемое состояние |
|---|---|
| Signup с дополнительным нейтральным полем | Новый аккаунт; ровно 8 полей ответа |
| PATCH с name и неизвестными/чужими идентификаторами | Изменяется собственный name, сохраняется свой id; ответ5; профиль Bob прежний |
| PATCH только с неизвестными полями | Оба полных профиля и даты до/после равны |
| Пустой PATCH | Полный профиль и даты до/после равны |
| GET с действующим bearer | Существующий пользователь этого токена |
| DELETE собственного профиля | Прежний ответ id/username/email и прежние правила удалённого субъекта |
| Restart только приложения | UUID, данные аккаунта и возможность входа сохранены |

Валидация, конфликты, пароль и обработка None не меняются. В частности None в PATCH не становится новой операцией очистки телефона.

## Конфигурация

Config содержит ровно auth/cache/database/logging/broker. Фикстура задаёт текущие переменные, переключает cwd на tmp_path и очищает get_settings до/после. Повторные вызовы get_settings возвращают один экземпляр в пределах теста. Дополнительное состояние удалённого хранилища не моделируется.

Redis blacklist токенов/TTL и публикация RabbitMQ остаются прежними.
