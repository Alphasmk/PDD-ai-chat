# Research: очистка остаточной тестовой логики

**Date**: 2026-09-27 | **Spec**: [spec.md](spec.md)

Исследованы рабочие файлы после реализации 002, а не прежний Git HEAD. Дополнительный исследователь проверил тесты, идентификатор миграции и исполняемое руководство только чтением. Секретные файлы окружения не читались. Новые технологии и внешние источники для локальной очистки не требуются; нерешённых вопросов нет.

## 1. Граница изменения

**Decision**: Удалить специальную логику изображений из семи файлов тестов и актуальных примеров проверки. Не повторять удаление приложения из 002.

**Rationale**: В source удалённая интеграция уже отсутствует; оставшиеся данные и отрицательные сценарии поддерживают ненужный контракт. Подтверждение пользователя распространяет очистку на тесты.

**Alternatives considered**: Оставить проверки недоступности прежних маршрутов или заменить хранилище — противоречит FR-001–FR-003. Удалить все контрактные тесты — ослабляет FR-004–FR-007.

Затронутые файлы:

- `tests/unit/settings_config_test.py`: перебор AWS-переменных, параметризация трёх состояний и проверки удалённой секции.
- `tests/unit/user_usecases_tests/register_user_test.py` и `get_current_user_from_db_test.py`: специальный `hasattr` удалённого поля.
- `tests/integration/auth_tests/signup_user_test.py`: устаревшее входное поле.
- `tests/integration/user_tests/edit_current_user_test.py`: данные изображения и специальные проверки отсутствия полей.
- `tests/integration/user_tests/removed_operations_test.py`: шесть пар method/path изображения и четыре термина в проверке OpenAPI.
- `tests/integration/settings/startup_test.py`: поиск удалённых терминов, запросы прежних маршрутов и PATCH с устаревшим полем.

## 2. Общая защита формы данных

**Decision**: Сохранить сравнение точных наборов восьми полей полного профиля и пяти полей PATCH. В существующих unit-тестах заменить специальные проверки атрибута сравнением имён полей возвращённого dataclass с фиксированным набором из контракта. Использовать `dataclasses.fields(result)` без преобразования в JSON и без `Any`.

**Rationale**: Любое лишнее поле вызывает несовпадение независимо от его названия. Ожидаемый набор задан требованиями, а не вычислен из той же модели, которую тест проверяет.

**Alternatives considered**: Проверка только значений нескольких полей пропускает дополнительные данные. Получение ожидаемого набора из текущей модели делает защиту тавтологической. Отдельный набор новых тестов не нужен: достаточно исправить существующие проверки.

## 3. Возможности и текущая личность

**Decision**: Сохранить точный allowlist восьми операций OpenAPI. Добавить такое же сравнение опубликованного `/openapi.json` в существующую контейнерную проверку. Из отрицательной параметризации убрать только сценарии изображения; оставшиеся сценарии чужих профилей и предыдущих административных операций сохранить.

**Rationale**: Allowlist обнаруживает любую новую операцию, включая произвольное имя пути. Контейнерная проверка подтверждает реальную опубликованную поверхность, а не только объект FastAPI в тестовом процессе.

**Alternatives considered**: Перечень запрещённых названий неполон и сохраняет удалённые понятия. Полное удаление `removed_operations_test.py` теряет проверку изоляции чужих аккаунтов из предыдущей функции.

## 4. Неизвестные поля

**Decision**: Использовать нейтральный `unsupported_field` со значением `ignored`, сохраняя отдельные попытки передать чужой `id`/`user_id`. Переименовать сценарий с одними устаревшими полями в сценарий с неизвестными полями. Проверять точную форму PATCH и полное равенство профиля до/после, включая даты; проверить пустой PATCH на ту же неизменность. При наличии Bob сохранить сравнение всего его профиля.

**Rationale**: Pydantic уже игнорирует дополнительные входные поля. Проверяется действующее поведение, а данные больше не подразумевают удалённую возможность.

**Alternatives considered**: Удалить весь unknown-input сценарий — нарушает FR-006. Менять `extra="ignore"` на запрет или добавлять специальные фильтры — меняет API и выходит за область 003.

## 5. Конфигурация

**Decision**: Заменить три AWS-варианта одним положительным тестом текущей конфигурации: пять секций `auth`, `cache`, `database`, `logging`, `broker`, корректные значения и кеширование `get_settings`. Сохранить временный cwd, явные значения действующих настроек через monkeypatch и очистку lru_cache до/после. Убрать импорт/перебор `os.environ`, генерацию устаревшего dotenv и проверку удалённой секции.

**Rationale**: Тест проверяет текущую сборку настроек и остаётся изолированным от пользовательского `.env`. Отдельная проверка неизвестных dotenv-полей здесь не нужна: эта очистка не меняет реализацию ConfigBase.

**Alternatives considered**: Заменить AWS другой тройной параметризацией — сохраняет ненужную структуру без нового пользовательского инварианта. Удалить тест полностью — теряет проверку конфигурации и кеширования.

## 6. История и хранение

**Decision**: Сохранить `users_no_images_20260927`, имя baseline, проверки его revision/head и Redis `.storage`. Исторические spec, plan и validation 001/002 сохранить. В quickstart 002 обновить только действующие инструкции и исполняемые примеры; README направить на новое руководство 003, оставив ссылку на прошлый отчёт явно исторической.

**Rationale**: Revision — идентификатор ранее применённой миграции. Изменение ради поиска нарушит FR-009. Token blacklist и Docker `image:` не относятся к пользовательскому изображению. Исторические результаты не доказывают следующую реализацию.

**Alternatives considered**: Глобальное удаление слова `image` повреждает историю, имена контейнерных образов и миграцию. Пересоздание основной БД не нужно: текущая users-only схема уже соответствует контракту.

## 7. Проверка реализации

**Decision**: Статический аудит ограничить действующими тестами и конфигурацией; результаты широкого поиска классифицировать по контексту. Выполнить Ruff, strict mypy, unit, интеграционные проверки с реальными PostgreSQL/Redis/RabbitMQ и контейнерный startup в отдельном Compose-проекте с tmpfs. Дополнить проверкой сохранения тестового аккаунта после restart только приложения.

**Rationale**: Такой набор подтверждает очистку и неизменность семи пользовательских сценариев. Он повторно использует существующую инфраструктуру, зависимости и baseline.

**Alternatives considered**: Один поиск строк не подтверждает поведение; SQLite/fakes не подтверждают production startup. Поддерживать прежнее число тестов искусственно не требуется: удалённые параметризованные сценарии закономерно уменьшают число проверок.

Новый отчёт реализации должен содержать фактические passed/failed/skipped и соответствие FR/SC; результаты 002 не копируются как результаты 003. На этапе планирования команды проверки приложения не запускались.
